## 五、工作法备忘（本批实测有效）

1. **动工前对照 HEAD 逐项核对**：PRD 条目是对着旧代码写的，T1、T2 共发现 9 处差异，见 PRD v1.1 §五。差异用提问让用户裁决，批准后先升 PRD 版本记下差异，再动手。
2. **派实现子代理**：全新上下文，任务书写全以下内容：
   - 必读文档；
   - 硬约束：不 commit / 不 push、范围文件清单、禁区、保持现有换行；
   - 逐项写清现状（文件:行）、批准方案、要先红的测试；
   - verify 命令；
   - 报告格式：Red 摘录、Green、四门禁、偏离之处。
   子代理的追加工作用 SendMessage 续给同一个子代理，它保留上下文。
3. **子代理报告不是结论**。主会话逐文件看 diff，亲自跑 `npm run verify -- --scope <清单> --base <开工前 HEAD>`。scope 要包含主会话自己改的文件（如 PRD）。
4. **独立复核 Red**：把承载行为的文件临时 `git show HEAD:<f> > <f>`，跑新测试，应当恰好新测试变红；然后从 scratchpad 备份还原，`git diff --stat` 确认已还原。
5. **提交**：`git commit -F <消息文件>`（Conventional Commits，`type: 范围 - 摘要`，末尾带 Co-Authored-By 行），提交后用 `git ls-files --eol` 确认 blob 是 `i/lf`。
6. **交付报告**：按 `docs/workflow.md` 第四节模板，附下一任务的方案和台账状态，等用户批准再开下一个任务。
