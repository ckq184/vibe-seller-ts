# vibe-seller → pi Agent SDK 迁移计划

原项目：`github.com/zpoint/vibe-seller`（Python FastAPI + Claude Code CLI 包装 + browser-use/CDP，约 5MB Python + 1MB TS）。
目标：以 `@earendil-works/pi-coding-agent` 为内核的 TypeScript 实现，**绞杀者模式**逐模块替换，每个阶段结束系统完整可运行。

## 等价性红线（移植时绝不能丢）

1. 紫鸟单账号互斥（原 `_active_ziniao_account_id`）——丢了会两个任务同时操纵一个浏览器；
2. wrapper 的 PATH 三层防逃逸 + 连续超时判不可恢复（rc75）；
3. 审核门"审计义务来自枚举清单而非报告形状"原则——防 agent 交形状正确的假报告；
4. `no_progress` 守卫与预算终止——本仓库已在 core loop 实现（同一意图连续失败 3 次判空转）；
5. 秘密永不进事件、日志、trace。

## 已定架构决定

- `~/.vibe-seller` 数据目录布局原样保留：知识库/技能/店铺数据/SQLite 不迁移，只换代码。
- 浏览器层（bash wrapper + CDP 多路复用代理）是独立进程：按外部进程托管 + ToolPort 封装，不当源码移植；最后再考虑 TS 化。
- React 19 前端零改动是硬约束：server 包必须逐字段对齐现有 REST + SSE 契约。
- 对 pi-coding-agent 技能基线契约的两处扩展（均有第一性理由，见 `packages/core/src/types.ts` 注释）：
  1. `run_started` 携带 `task`/`sessionId`——事件日志是唯一事实源，回放必须能自足重建 AgentState；
  2. `respond` 决策可选携带 `partial.missingMaterial`——`run_completed` 区分 complete/partial，部分结果绝不冒充成功。
- 事件先落 RunLog 再推消费者；Session 快照只是缓存，允许落后。
